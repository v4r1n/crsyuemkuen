# Project instructions

## Mission

Build and maintain CRS Yuem-Kuen on Next.js/Vercel and private Supabase PostgreSQL/Storage (Singapore). Preserve borrowing rules and rollback evidence. Subsequent user requests authorize glass UI, linked passwords, email security, explicitly public Guest projections and transactional notifications. Read `docs/IDENTITY_EXPERIENCE.md` when changing or activating these features.

## Non-negotiable rules

- Use the approved free-first infrastructure. Provisioning paid resources requires a new user decision.
- Treat one Equipment row as one physical asset. `quantity` is always `1`; identical assets share an SKU.
- Use the canonical English enum values from `src/Constants.gs` in storage and translate only in the UI.
- Derive protected visitor identity through verified server-side Google OIDC or the current secure password credential linked to the same existing User. Google retains signature, issuer, audience, expiry, nonce and authoritative email checks. Password retains current email/generation, throttles, lockout and required-change restrictions. Client email/role assertions and platform active-user fallbacks never authorize visitors.
- Protect sign-in with state, nonce, PKCE, one-time flow records, flow-bound OTP HMAC, and an opaque application session. PostgreSQL stores hashes of browser/session secrets and transient server-only flow data. Preserve the current browser session/remember behavior, absolute six-hour ceiling, and reauthorization on every RPC. Never send Google tokens or credentials to the browser or URLs.
- Deny access when the authorization proof or application session is missing, invalid, expired, replayed, issued to another OAuth client, outside `ALLOWED_DOMAINS`, non-authoritative for the asserted email, absent from Users, inactive, or insufficiently privileged. Never auto-provision a visitor.
- Enforce authorization in every server mutation. Hiding a button is not authorization.
- Run every workflow in `server/db.mjs` transaction with its transaction-scoped advisory lock acquired before authoritative reads. Validate source state/version and commit projection, History, counters and Operation atomically.
- Never hard-delete Equipment, Borrow, Users, Categories, IncludedItems, or History records. Use lifecycle statuses.
- History is append-only and generated by domain services, never by the browser.
- `server/domain.mjs` is the repository/runtime seam. Source-controlled legacy domain services execute in an isolated per-request context; client input is never executable code. New runtime never calls Apps Script, Sheets or Drive. Keep legacy source unchanged unless explicitly porting a rule with regression coverage.
- Cache only performance data. Never use cached roles, availability, active-loan state, or counters for correctness.
- RPC methods are an explicit allowlist of narrow guarded wrappers. Guest reads use the explicit public projection only; default visibility is private. Keep database/Storage/SMTP/OTP secrets server-only, `crs` schema unexposed, RLS enabled with no client policies, and images private. Persist hashes and non-secret mail metadata only; OTP and temporary-password bodies exist only during delivery.
- QR/share/navigation use explicit `WEB_APP_URL`, never browser host/path. Image file ID is authoritative; capability delivery rechecks session/reference/version and verifies private bytes. Commit replacement before queued cleanup; uncertainty is not proof of absence.
- Configuration lives in local `.env.local` and Vercel server environment. Credentials, actual resource IDs, XLSX/ZIP data and generated private backups stay out of Git. Read `docs/MIGRATION_NEXT_SUPABASE.md` before provisioning, importing, backup/restore, deployment or cutover; its acceptance gates distinguish source preparation from completion.

## V1 state model

```text
Borrow:    PENDING_APPROVAL -> APPROVED -> CHECKED_OUT -> RETURN_REQUESTED -> RETURNED
Equipment: AVAILABLE        -> PENDING  -> RESERVED     -> BORROWED         -> RETURNING
```

Alternate transitions are `PENDING_APPROVAL -> REJECTED`, admin direct return from `CHECKED_OUT`, and inspected return to `AVAILABLE`, `DAMAGED`, `MAINTENANCE`, or `LOST`. Overdue is derived from due date and is never persisted as the primary status.

## Source layout

- `app/`, `server/`, `supabase/`: Next.js routes, authorization/adapters, private PostgreSQL schema.
- `src/*.gs`, `src/*.html`: preserved domain/UI baseline; `tools/build-web.mjs` adapts explicit transport seams into ignored `public/crs/` build output.
- `tools/`: preview/apply importer and private backup/restore commands.
- `docs/`: architecture, schema, workflows, operations, decisions, migration notes, memory, and changelog.
- `tests/`: local contract/static tests and the manual acceptance matrix.

## Coding conventions

- New server modules use Node.js 22+ ESM. Preserved `src/` remains compatible with its legacy tests/runtime.
- Store instants as ISO-8601 UTC strings and business dates as `yyyy-MM-dd` in `Asia/Bangkok`.
- Preserve formula-injection escaping in domain text and render with `textContent` or escaped templates. Archive raw originals separately; archive never grants authorization.
- Return serializable plain RPC objects; preserve old envelope/error/DTO contracts.
- User-facing errors are concise Thai messages with stable error codes and a request ID; detailed stacks stay in execution logs.
- Commits follow Conventional Commits. Do not create Git tags unless the user later requests one.

## Session End Protocol

Complete this checklist at the end of every phase:

1. Run the checks relevant to the phase and record the result in `docs/MEMORY.md`.
2. Update `docs/MEMORY.md` with completed scope, current constraints, and the exact next phase.
3. Update `docs/CHANGELOG.md` under `Unreleased`.
4. Add or supersede decisions in `docs/DECISIONS.md` when architecture or contracts changed.
5. Confirm no secrets, real IDs, or unrelated files are staged.
6. Commit only phase files with a Conventional Commit message and push the current feature branch.
7. Do not tag the commit.
