# Calendar reminders do not invent workflow History

On 2026-10-22 the operator accepts borrower reminders one day before due date and once per overdue Thailand business day, until inspected return. Derive these from current CHECKED_OUT/RETURN_REQUESTED Borrow state, not synthetic History. Preserve the existing owner inbox and independently opt-in external channel; security mail is unaffected. Durable reminder notices carry nullable History plus explicit due/day source evidence with a unique recipient/Borrow/action/due/day key. Existing event notices still require real History.

Use the shared locked transaction to create at most 100 current-day reminders per invocation and commit notice/outbox together. Repeated owner inbox reads and the existing authenticated daily worker provide opportunities; missed days are not backfilled. Worker and inbox recheck current custody, due date and Thailand day, so returned, rescheduled or stale reminders are not delivered/displayed. This bounded free-first design is not an exact-time scheduler or unlimited backlog guarantee. No provider calls hold the business lock; existing delivery uncertainty, opt-in and session/device rules remain.

Additive schema precedes new runtime, with a verified backup and no old-row rewrite. Format-4 generic row snapshots include the new nullable columns; older snapshots omit them and restore as null for genuine History notices. Restoring never replays outbox or enrolls external channels. `DUE_REMINDERS_ENABLED` is independent of global external delivery; Production diagnostic renewal still requires explicit operator approval and real device receipt remains a separate gate.
